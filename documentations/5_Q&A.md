+ 在CMake中为什么要将模块独立成library？
  1. 会随着项目的增长，编译时间增加。只修改一个文件，需要整个程序重新链接。
  2. 无法单独测试模块。
  3. 对于未来拓展困难。

+ 关于log，数据库，json，测试的部分放在third_libs中？
  1. 因为这部分并不属于笔记系统的业务，而是软件运行的基础设施，不是业务代码。

+ 在main.cpp与NoteManager之间加入Application层的原因？

  1. 不加Application，main会承担太多的责任，需要：

  ```
  1.解析参数
  	add
  	note
  	test.md
  2.创建 Note 对象
  3.调用 Storage
  4.更新 Index
  5.输出结果
  ```

  加入Application层之后，

  ```
  CLI
  负责：
  用户交互
  命令解析
  输出显示
  
  Application
  负责：
  业务流程编排
  
  Core
  负责：
  领域逻辑
  ```

  CLI不知道文件怎么保存，索引怎么更新，搜索怎么实现，而Application不知道用户输入从哪里来的。

  2. 方便未来GUI直接可以接入Application复用。

+ 关于Note对象，设计成贫血模型还是领域模型？

  1. 贫血模型：对象中只有数据，所有逻辑放在管理类中；优点是，简单，数据传输时转换简单，测试容易；缺点是，业务逻辑分散。
  2. 领域模型：对象中有数据加行为；优点是，封装状态，高内聚，符合对象思想。
  3. 对于Note，可以设计为轻量领域模型，有部分行为，但是不包含文件保存，sqlite操作，索引构建，搜索等。
